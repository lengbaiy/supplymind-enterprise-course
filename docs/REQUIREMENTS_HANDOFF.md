# SupplyMind 企业级功能需求与开发交接文档

> 文档版本：v1.0  
> 更新时间：2026-08-18  
> 适用仓库：`supplymind-enterprise`  
> 当前原则：后续开发优先完成真实业务功能、数据闭环和浏览器验收，不再以目录整理或框架拆分作为主要交付目标。

## 1. 项目定位

SupplyMind 是面向制造企业供应链团队的多租户数据分析助手。组织管理员接入 MySQL/PostgreSQL 只读数据源，维护供应链指标口径和制度文档，分析师使用自然语言提问，系统通过真实模型、RAG、Schema 检索和安全 SQL Guard 生成可追溯分析结果，并输出图表、洞察和报告。

本项目是企业课程案例，目标是让学员能够从空环境启动系统、接入演示库、完成一次真实分析、追踪 Agent 执行过程、查看报告和审计记录。它不是生产 SLA、灾备或大规模压测项目。

## 2. 业务目标

### 2.1 核心业务闭环

1. 组织管理员登录并管理本组织成员、角色、配额和资源。
2. 组织管理员接入 MySQL 或 PostgreSQL 只读数据源。
3. 系统同步表、列、主外键、索引、注释等元数据，不复制业务全量数据。
4. 组织管理员维护知识库并上传 PDF、Markdown、TXT 口径文档。
5. 系统执行文本提取、分块、Embedding 和向量检索。
6. 分析师提交供应链问题，系统通过八阶段 Agent 流程生成安全 SQL 并执行。
7. 分析结果包含 SQL、行数据、图表规格、洞察、RAG 引用和审计记录。
8. 用户查看 Markdown 报告，异步生成 PDF 并按组织和角色下载。
9. 管理人员查看供应链大屏、筛选指标、刷新缓存和追踪系统状态。

### 2.2 首期明确不做

- 任意拖拽式 BI 编辑器。
- 向用户数据源写入业务数据。
- 跨组织共享数据、知识库、分析运行或报告。
- 实时流计算、私有模型训练和全量 DB-GPT 功能迁移。
- 生产级 SLA、灾备演练和大规模压测承诺。

## 3. 用户、角色与权限

| 角色 | 真实职责 | 当前状态 |
|---|---|---|
| 平台管理员 | 管理组织、模型配置、平台级审计 | 基础角色校验已完成，平台管理界面未完整交付 |
| 组织管理员 | 管理成员、数据源、知识库、大屏、配额和组织审计 | 基础组织管理已完成，成员邀请和完整 CRUD 未完成 |
| 分析师 | 选择授权资源、发起分析、查看结果、创建报告 | 基础分析流程已完成，资源选择和失败重试需完善 |
| 只读成员 | 查看授权结果、报告和大屏 | 基础读取权限已完成，前端无权限态需完善 |

所有资源读取必须同时满足：JWT 组织上下文、服务层 `tenant_id` 过滤、PostgreSQL RLS。跨组织访问统一返回 `404`，不能泄露资源是否存在。

## 4. 当前技术和运行基线

- 后端：Python 3.12、FastAPI、SQLAlchemy、Alembic、Pydantic。
- 异步任务：Celery + Redis。
- 平台数据库：PostgreSQL 16 + pgvector 运行基线。
- 前端：React、TypeScript、Vite、ECharts。
- 模型：OpenAI 兼容 Chat/Embedding 接口，配置缺失或调用失败必须 fail-closed。
- 认证：本地 JWT、刷新令牌、OIDC 适配器基础。
- 运行：Docker Compose；Helm 模板和 Prometheus/Grafana 已存在基础配置。
- 演示库：Compose 内 MySQL 和 PostgreSQL 供应链数据库，包含供应商、采购订单、物料、生产工单、库存、质检、销售订单和交付计划。
- 访问地址：前端 `http://localhost:5173`，API `http://localhost:8000`，API 文档 `http://localhost:8000/docs`。

## 6. 未完成的真实功能需求

以下内容是新窗口的主要开发范围，优先级高于继续整理目录。

- 成员邀请：邮箱、角色、邀请状态、过期时间、重新发送。

- 前端成员列表、邀请弹窗、角色编辑、停用确认和无权限页。

### F02 OIDC 完整登录

- OIDC discovery、授权码回调、state/nonce 校验、过期和重放拒绝。
- issuer subject 到本地用户的稳定映射。
- 首次登录自动关联组织或进入待审批状态。

- 增加回调集成测试和浏览器验收。

### F03 数据源真实元数据管理

- 四步向导改为真实步骤状态：连接信息、网络/TLS、表白名单、测试确认。
- Schema 浏览器展示表、列、类型、主键、外键、索引、注释和采样限制。
- 白名单从同步元数据中选择，禁止只依赖手工逗号文本。
- Schema 同步进入 Celery，保存同步任务、开始时间、结束时间、失败原因。
- 查询试跑展示耗时、最大行数、超时和脱敏状态。
- 数据源状态包括 active、testing、syncing、disabled、failed。
- 连接密码不返回前端，错误信息不得包含密码或完整连接串。

### F04 知识库管理闭环

- 知识库列表分页、名称/状态筛选、文档数、片段数、最近摄取时间和负责人。
- 文档删除、归档、版本替换和重复文件提示。
- 摄取任务取消、重试、死信处理和任务详情。
- Embedding 模型版本、维度、批次耗时和失败原因可追踪。
- 口径维护字段：指标名称、定义、公式、单位、适用工厂、适用产品线、生效时间。
- 检索结果可展开原文，显示引用 ID、页码/段落和文档版本。
- 归档知识库不能被新的分析任务选择。

### F05 分析真实业务闭环

- 分析创建页必须让用户选择数据源和知识库，不再默认取第一个资源。
- 预置六类问题模板：生产达成率、缺料风险、供应商交付、库存周转、质量合格率、订单履约。
- SSE 支持断线重连、运行状态查询和页面刷新后恢复时间线。
- SQL 草案与最终 SQL 分离展示，记录 Guard 拒绝原因和最多两次重写。
- 图表规格真实渲染折线、柱状、排行、异常清单，不只展示 JSON。
- 洞察拆分为事实、风险、建议、证据；无行数据时不能生成确定性结论。
- 失败运行支持重新运行，幂等键防止重复执行。
- 分析运行详情显示数据源、知识库、模型版本、提示词版本、Trace ID 和审计事件。

### F06 报告实际交付

- 报告详情显示完整 Markdown、SQL、图表、洞察、引用和分析运行信息。

- PDF 失败支持重试，重试沿用幂等键，不生成重复文件。
- 生产环境接入 S3/MinIO 适配器，数据库只保存对象键、checksum 和状态，不保存不必要的绝对路径。
- 报告列表支持标题、状态、创建人、时间和运行 ID 筛选。

## 8. 核心验收场景

### 场景 A：数据接入

组织管理员登录，创建演示 PostgreSQL 数据源，完成连接测试和 Schema 同步，选择允许表，查看列/主键/注释，停用后验证查询被拒绝。

### 场景 B：知识库

组织管理员创建“供应链指标口径”知识库，上传 Markdown/PDF，等待 Worker 完成摄取，检索“生产达成率定义”，看到文档、片段、分数和位置；归档后不能用于新分析。

### 场景 C：真实分析

分析师选择演示数据源和知识库，提交“近 30 天各工厂生产达成率与缺料风险”，系统返回运行 ID、八阶段时间线、安全 SQL、查询行、图表、事实/风险/建议、RAG 引用和报告 ID；模型未配置时必须返回可审计失败，不得返回模拟答案。

### 场景 D：报告交付

用户打开报告详情，查看 Markdown、SQL、图表和引用，发起 PDF 导出，看到任务状态，完成后下载；第二组织使用同一报告 ID 必须得到 `404`。

### 场景 E：大屏和监控

用户按工厂、产品线和时间范围筛选五类指标，确认缓存时间和刷新状态；组织管理员发起刷新，Worker 失败时页面显示失败原因和 Trace ID；系统状态页显示依赖健康情况。

## 9. 新窗口执行顺序

新窗口不要从目录整理开始，按以下真实功能顺序执行：

1. **F01 成员管理闭环**：邀请、角色变更、启停、配额使用量和前端操作确认。
2. **F03 数据源元数据**：真实 Schema 浏览、同步任务、白名单选择、查询试跑。
3. **F04 知识库闭环**：文档归档/删除/版本、任务取消、口径字段、引用原文。
4. **F05 分析闭环**：资源选择、模板、SSE 重连、真实 ECharts、失败重试。

## 10. 完成定义与证据要求

一个功能模块只有同时满足以下条件，才可以在后续文档中标记为“已完成”：

1. 后端接口包含组织隔离、角色授权、输入校验、审计和可理解的错误响应。
2. 数据库变化由 Alembic 管理，并有跨组织拒绝或权限回归测试。
3. 前端存在真实操作路径，而不是静态占位、默认假数据或仅展示 JSON。
4. 异步流程具备任务状态、幂等键、失败原因和重试/取消策略（适用时）。
5. Docker 环境完成最小验收，且三模块一组执行统一回归检查。
6. 文档记录接口、数据模型、配置、验收步骤和已知限制，并形成独立 commit。

不得把“页面能打开”“接口返回 200”“静态默认数据”单独作为功能完成证据。模型、数据源或 Embedding 未配置时，系统必须明确失败并留下审计记录，不得以模拟结果替代真实能力。
