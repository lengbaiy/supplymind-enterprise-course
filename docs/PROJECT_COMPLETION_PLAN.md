# SupplyMind 项目完善实施计划

## 1. 计划目的

当前项目已经具备可运行的企业级演示骨架、Docker 环境、数据源连接、知识库上传、分析 SSE、报告和监控基础，但控制台仍偏向“垂直演示切片”。本计划依据 `docs/IMPLEMENTATION_PLAN.md`、`docs/ARCHITECTURE.md` 和课程验收要求，把页面和后端能力补齐为一套可连续操作、可测试、可授课的企业课程案例。

本轮目标不是一次性重写，而是按领域切块实现，每个切块都可以独立启动、测试和回滚。

## 2. 完成边界

### 必须完成

- 项目管理：组织、成员、角色、配额、数据源、知识库、大屏和审计的统一管理入口。
- 知识库：知识库列表、详情、文档上传、摄取状态、失败重试、检索预览、引用定位和知识库权限。
- 数据源：MySQL/PostgreSQL 创建、连接测试、Schema 同步、表白名单、只读账号提示、删除/停用和同步记录。
- 分析会话：问题输入、数据源/知识库选择、八阶段 Agent 进度、SQL Guard 结果、表格、图表、引用、洞察和报告。
- 报告中心：报告列表、详情、Markdown、引用、PDF 导出任务、下载状态和权限拒绝页面。
- 供应链大屏：五类预置组件、筛选条件、缓存时间、刷新任务、失败状态和数据覆盖提示。
- 审计与系统状态：按动作/资源/时间筛选，事件详情，API/Worker/模型/Redis/数据库健康状态。
- Docker/Helm/CI 和课程文档：空环境复现命令、迁移检查、浏览器验收、回滚说明和讲师材料。

### 明确不做

- 任意拖拽 BI 编辑器。
- 向用户数据源写入业务数据。
- 跨组织共享资源。
- 实时流计算、私有模型训练和全量 DB-GPT 功能迁移。
- 生产 SLA、灾备演练和大规模压测承诺。

## 3. 统一页面信息架构

### 3.1 应用壳

- 登录页：本地账号登录、OIDC 登录入口、错误提示、加载态。
- 顶部栏：当前组织、当前角色、刷新、系统状态、退出。
- 左侧导航：运营总览、项目管理、数据源、知识库、分析会话、报告中心、大屏、组织与审计。
- 移动端：底部导航只保留高频入口，低频管理项进入“更多”。
- 所有页面必须有 loading、empty、error、permission denied 和 success feedback 状态。

### 3.2 项目管理页

项目管理是组织管理员的控制台入口，不等同于业务分析页面。

- 项目概览：组织名称、成员数、数据源数、知识库数、报告数、月度用量和配额。
- 成员管理：成员列表、角色徽标、启用/停用、角色修改、邀请入口、操作确认。
- 角色矩阵：平台管理员、组织管理员、分析师、只读成员的权限说明和实际按钮状态。
- 资源概览：数据源、知识库、大屏配置的状态摘要和快捷跳转。
- 配额设置：分析并发数、每日运行次数、文档大小和保留期限，保存前显示影响范围。
- 操作日志：从项目管理页直接跳转过滤后的审计事件。

后端接口：组织详情、成员 CRUD/角色变更、配额读取/更新、资源计数、权限矩阵和审计跳转参数。所有接口必须校验组织上下文和角色。

## 4. 知识库完善方案

### 4.1 列表页

- 展示名称、描述、文档数、已完成片段数、最近摄取时间、负责人和状态。
- 支持按名称/状态筛选和分页。
- 支持创建、进入详情、归档；归档知识库不能被新的分析任务选择。
- 没有知识库时提供创建入口，不显示无功能的装饰卡片。

### 4.2 详情页

- 概览：知识库状态、文档数量、片段数量、Embedding 模型版本和最近错误。
- 文档列表：文件名、类型、大小、上传人、上传时间、摄取状态、片段数、失败原因。
- 上传：PDF/Markdown/TXT，大小和扩展名校验，上传进度，重复文件提示。
- 任务操作：刷新状态、失败重试、取消排队任务；重试必须沿用幂等键。
- 检索预览：输入问题，展示文档名、片段文本、相似度、页码/段落位置和引用 ID。
- 口径维护：指标定义、计算公式、工厂/产品线术语和适用范围。

### 4.3 后端补齐

- `Document` 增加文件大小、语言、版本、失败原因和归档状态字段。
- `IngestionTask` 增加重试上限、下次重试时间、死信状态和耗时字段。
- 文本提取、分块、Embedding、pgvector 写入全部进入 Celery。
- 检索结果统一返回 `document_id`、文件名、片段 ID、文本、分数和位置。
- 组织管理员才能上传/删除/重试；分析师只能检索授权知识库；只读成员只能查看引用。
- Embedding 未配置或失败时拒绝检索，并写入可审计错误，不返回模拟结果。

## 5. 数据源完善方案

- 创建向导分为连接信息、TLS/网络、表白名单、连接测试四步。
- 默认显示只读账号要求、允许主机/CIDR、连接超时和安全提示。
- 详情页展示连接状态、最后测试时间、最后 Schema 同步时间、白名单表和失败原因。
- Schema 浏览器展示表、列、类型、主键、外键、索引、注释和采样限制。
- 支持停用/删除数据源；已被分析运行引用的数据源只允许停用，不允许物理删除。
- 查询试跑只允许分析师及以上角色，结果显示扫描限制、耗时和脱敏提示。
- 后端补齐 DataSource 状态、同步任务、连接测试审计和删除保护。

## 6. 分析会话完善方案

### 6.1 创建分析

- 选择数据源、知识库和问题模板。
- 提供六个供应链问题模板：生产达成率、缺料风险、供应商交付、库存周转、质量合格率、订单履约。
- 提交后立即返回 `analysis_run_id`，前端用 SSE 订阅，不阻塞页面。

### 6.2 结果页

- 时间线：路由、RAG、Schema、SQL 规划、SQL Guard、查询、洞察、报告八阶段。
- SQL 草案与最终 SQL 分开显示，展示允许表、拒绝原因、重写次数和查询限制。
- 结果表支持列宽、横向滚动、空结果解释和最多 500 行提示。
- 图表按后端规格渲染 ECharts，至少支持折线、柱状、排行和异常清单。
- 引用面板显示知识库文档、片段、分数、页码/段落并支持展开原文。
- 洞察面板区分事实、风险、建议和证据，不允许没有数据依据的结论。
- 报告操作：生成 Markdown、排队 PDF、查看导出状态、下载和复制运行 ID。
- 失败结果保留失败阶段、错误解释、审计 ID和重新运行按钮。

## 7. 报告中心完善方案

- 列表筛选标题、状态、创建人、时间和分析运行 ID。
- 详情页展示 Markdown 正文、SQL、图表缩略图、RAG 引用和审计信息。
- PDF 导出显示 queued/running/completed/failed，失败可重试。
- 下载前校验组织和角色；跨组织资源返回统一 404，不泄露存在性。
- 生产对象存储使用 S3 适配器，开发环境使用 Docker 卷。

## 8. 大屏完善方案

固定五类组件：采购交付、生产达成、库存健康度、质量合格率、订单履约。

- 顶部显示数据更新时间、缓存时间和刷新状态。
- 筛选：时间范围、工厂、产品线；筛选值来自数据源元数据，不写死在前端。
- 指标卡点击后跳转分析会话并带入对应问题。
- 趋势和排行组件支持查看明细；异常清单支持跳转到数据源查询上下文。
- 刷新调用异步任务，默认五分钟缓存，前端显示排队/成功/失败。
- 组织管理员可保存大屏配置；分析师和只读成员只能查看授权配置。

## 9. 审计与系统状态

- 审计筛选动作、资源类型、操作者、时间区间和运行 ID。
- 事件详情显示组织、操作者、角色、Trace ID、输入摘要、结果摘要和失败原因，禁止显示密钥与完整业务数据。
- 系统状态页显示 API、Worker、PostgreSQL、Redis、模型、Embedding、MinIO、MCP 和数据源依赖状态。
- 对每个依赖显示超时、降级和最近错误；状态接口本身不能阻塞主页面。

## 10. 数据与权限验收矩阵

| 场景 | 组织管理员 | 分析师 | 只读成员 |
|---|---:|---:|---:|
| 管理成员/角色 | 是 | 否 | 否 |
| 创建/停用数据源 | 是 | 否 | 否 |
| 上传/重试知识文档 | 是 | 否 | 否 |
| 发起分析 | 是 | 是 | 否 |
| 查看授权结果/报告/大屏 | 是 | 是 | 是 |
| 导出 PDF | 是 | 是 | 按授权 |
| 查看组织审计 | 是 | 否 | 否 |

每一个资源读取都必须同时验证 JWT 组织上下文、服务层 `tenant_id` 和 PostgreSQL RLS；第二组织不能通过 ID、文件路径、报告导出 ID 或 SSE 运行 ID读取第一组织资源。

## 11. 分块实施顺序

### P01：项目管理与应用壳

- 页面：组织概览、成员、角色矩阵、配额、资源摘要。
- 后端：组织详情、资源统计、配额 DTO、固定权限矩阵和配额审计。
- 前端：项目管理页展示真实组织资源、配额表单和角色权限矩阵。
- 待补：成员邀请和完整成员 CRUD 在身份与租户切块统一实现。
- 验收：不同角色看到的按钮和接口结果一致；`0004_organization_quotas` 已迁移。

### P02：知识库完整生命周期

- 页面：列表、详情、归档/恢复、任务状态、失败重试、检索预览、引用详情。
- 后端：文档元数据、任务重试/死信/耗时、知识库删除保护和审计。
- 验收：上传重复文件不重复切片，Embedding 失败可追踪，归档资源不可被新分析选择，跨组织返回 404。

### P03：数据源向导与 Schema 浏览器

**状态：已完成（2026-08-18）。**

- 页面：四步接入、详情、白名单、Schema 浏览、停用。
- 后端：同步任务记录、删除保护、连接状态。
- 验收：PostgreSQL/MySQL 演示源均可测试、同步、查询，危险 SQL 全部拒绝。

### P04：分析会话完整结果

**状态：已完成（2026-08-18）。**

- 页面：模板问题、八阶段时间线、SQL Guard、表格、图表、引用、失败重试。
- 后端：AgentStep 输入摘要/耗时/版本完整持久化，SSE 事件契约固定。
- 验收：真实模型完成“近 30 天各工厂生产达成率与缺料风险”。

### P05：报告中心与文件权限

**状态：已完成（2026-08-18）。**

- 页面：列表、详情、导出状态、下载失败重试。
- 后端：PDF 任务幂等、S3/本地存储适配、租户校验。
- 验收：报告和文件不能跨组织访问。

### P06：大屏交互与异步刷新

- 页面：五类组件、筛选、明细跳转、刷新状态。
- 后端：聚合任务、五分钟缓存、失败记录。
- 验收：筛选和刷新不会阻塞 API，结果可追溯。

### P07：审计、系统状态与错误体验

- 页面：审计筛选/详情、健康依赖、无权限/空/错误页面。
- 后端：Trace ID、结构化错误、依赖超时和降级。
- 验收：每个外部动作都有审计，密钥和业务明细不泄露。

### P08：浏览器 E2E、部署和课程交付

- Playwright/browser 验收完整用户路径。
- Compose 在 16GB 设备复现，Helm lint/template 和探针验证。
- CI 增加测试、Ruff、前端构建、迁移检查、依赖和镜像扫描。
- 更新课程课件、讲师稿、起止代码、作业、部署手册、答辩清单和许可证说明。

## 12. 每个切块的完成标准

- 代码只修改对应领域和兼容入口，新增接口有 DTO/权限/审计。
- Docker 环境启动并完成该切块的最小验收。
- 后端容器内测试与 Ruff 通过。
- 前端改动前重新读取 taste-skill 和 impeccable，执行 Impeccable context/detect，`npm run build` 通过。
- 迁移变化通过 `alembic upgrade head` 和空库检查。
- 更新 `docs/IMPLEMENTATION_PLAN.md` 和本计划的状态。
- 单独 commit，提交信息包含切块编号，例如 `feat: P02 complete knowledge lifecycle`。

## 13. 当前优先级

下一步从 P01 开始：先完成项目管理页面和组织配额/资源摘要接口，再进入 P02 知识库详情与任务重试。不要继续在单一 `frontend/src/main.tsx` 中堆叠页面；每完成一个切块，就把页面迁移到对应 `frontend/src/features/<domain>`，保留兼容入口直到浏览器验收通过。
