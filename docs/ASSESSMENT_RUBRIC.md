# SupplyMind 评分标准

总分 100 分。评分重点是企业级工程能力，而不是页面数量或模型回答是否华丽。

## 1. 架构与边界 15 分

| 分值 | 标准 |
| ---: | --- |
| 5 | 能解释 API、Worker、前端、平台库、客户数据源和对象存储边界 |
| 4 | 新代码放在正确领域模块，没有破坏 `/api/v1` 兼容 |
| 3 | 能说明模块化单体的取舍和后续拆分条件 |
| 3 | 文档同步更新，能让下一组继续开发 |

## 2. 安全与多租户 20 分

| 分值 | 标准 |
| ---: | --- |
| 5 | 所有资源读取都校验组织上下文和角色 |
| 4 | 跨组织访问统一返回 `404`，不泄露存在性 |
| 4 | SQL Guard 覆盖危险 SQL、越权表和非只读语句 |
| 3 | 密钥不进前端、不进提交、不进日志 |
| 4 | 新增权限场景有自动化测试 |

## 3. AI 与数据分析工程 15 分

| 分值 | 标准 |
| ---: | --- |
| 4 | 分析流程保留八阶段轨迹和失败原因 |
| 4 | RAG 结果包含文档、chunk、位置和分数 |
| 3 | MCP 工具有明确输入/输出 Schema 和角色限制 |
| 2 | 模型或 Embedding 不可用时 fail-closed |
| 2 | 报告结论能追溯 SQL、行数、图表和引用 |

## 4. 异步、可靠性与审计 15 分

| 分值 | 标准 |
| ---: | --- |
| 4 | 任务状态机清楚，重复投递不产生重复副作用 |
| 3 | 失败任务有错误摘要、Trace ID 和重试入口 |
| 3 | 外部依赖异常能在系统状态页或日志定位 |
| 3 | 高风险操作写入审计且敏感字段脱敏 |
| 2 | 能说明哪些故障需要人工复核 |

## 5. 前端产品与可用性 10 分

| 分值 | 标准 |
| ---: | --- |
| 3 | 页面支持 loading、empty、error、forbidden 状态 |
| 2 | 桌面和移动导航都可用 |
| 2 | 表格、筛选、任务状态和下载操作可被用户理解 |
| 2 | 错误提示包含可追踪 Trace ID |
| 1 | 无明显布局溢出和不可点击控件 |

## 6. 测试与交付 15 分

| 分值 | 标准 |
| ---: | --- |
| 4 | 后端测试和 Ruff 通过 |
| 3 | 前端单测、构建和 E2E 通过 |
| 2 | Compose config 和健康检查通过 |
| 2 | Helm lint/template 通过 |
| 2 | CI、安全扫描或依赖检查没有被绕过 |
| 2 | 能生成本地验收报告 |

## 7. 答辩表达 10 分

| 分值 | 标准 |
| ---: | --- |
| 3 | 能清楚演示一个真实业务闭环 |
| 2 | 能解释关键工程取舍 |
| 2 | 能复盘一个失败和修复过程 |
| 2 | 能说明上线、回滚和数据保护流程 |
| 1 | 回答准确，不夸大项目能力 |

## 扣分项

- 提交密钥、令牌、客户数据或完整业务导出：直接不通过。
- 使用模拟结论冒充真实模型或真实数据结果：最多 60 分。
- 跨组织资源可见或可下载：最多 50 分，必须先修复。
- 绕过测试或删除失败测试：最多 70 分。
- 大范围重构但没有验收证据：最多 75 分。

## 加分项

最多加 10 分：

- 增加高价值的失败演练并自动化。
- 补齐 CI 中之前缺失的发布闸门。
- 为复杂问题提供清晰的架构图或时序图。
- 把一个手动验收步骤变成可重复脚本。
